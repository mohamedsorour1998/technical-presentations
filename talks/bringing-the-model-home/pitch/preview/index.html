WHY BOTHER

The bill is the hook.
It is not the reason.

  • Everyone starts here: the invoice went up and the meter never stops.
  • But cost alone is a weak argument — inference keeps getting cheaper.
  • The durable reason is control: over your data, and over your dependencies.

This talk is the second argument, not the first.

THE STACK

Four layers, bottom to top

your agentanything speaking the OpenAI chat protocol — Claude Code, OpenCode, Xcode, curl
mlx_lm.serveran OpenAI-compatible HTTP server on localhost. Tool calling, streaming
mlx-lmload, run, quantize and fine-tune language models
mlxApple's array framework — Metal kernels, unified memory

Swap the base URL and the agent cannot tell the difference. That is the whole integration story.

5
THE ONE IDEA

Unified memory is why a laptop
can do this at all

DISCRETE GPU

Model weights live in VRAM.
Copy across PCIe to use them.
Far more bandwidth — but you get
12, 16, 24 GB and then you stop.

APPLE SILICON

CPU and GPU share the same bytes.
No copy, ever.
Less bandwidth — but the ceiling is
however much RAM you bought.

Generation speed is a memory-bandwidth problem. Model size is a capacity problem. Apple trades the first for the second — and capacity is what decides whether a model runs at all.

7

It ran fine, and
the output was wrong.

  • Exit code 0. No warning. A plausible-looking transcript.
  • One 12-word phrase repeated 19 times — the decoder had latched onto its own output.
  • Fix: --condition-on-previous-text False

Local inference has operational failure modes. So it needs a validation gate, like anything else you put in a pipeline.

8
THE GATE

Fifteen lines that would have
caught it

Count every 12-word phrase in the output. If any appears more than twice, fail the run.

$ python3 scripts/check_transcript.py bench/demo-60s.txt
transcript repetition check passed
 
$ python3 scripts/check_transcript.py contaminated.txt
FAIL: phrase repeated 19 times

A model you host is infrastructure. Infrastructure gets a health check.

9
DEMO TWO

A local model, calling tools

# terminal 1 — the server, pre-warmed before I walked up
$ mlx_lm.server --model mlx-community/Qwen3.5-4B-MLX-4bit --port 8080
 
# terminal 2 — the agent, pointed at localhost
$ export OPENAI_BASE_URL=http://127.0.0.1:8080/v1
  • The agent asks the model what to do. The model names a tool. The agent runs it.
  • That loop is the whole idea — and every turn of it is on this laptop.
10
THE CEILING

Where local loses. Plainly.

  • Hard, long tasks. A published test had a local model produce 47 compile errors, retry, then give up.
  • Speed. Roughly 5× slower to finish the same agentic task than a frontier model.
  • Size. 16 GB is shared with your OS. The good coding models do not fit.
  • Your time. Smaller models need smaller, better-specified tasks.

If I claimed this replaced a frontier model, the first person to try it would find out I was wrong. It does not. It does something else.

11
THE RULE

Bring it home when three
things are true

01
The task is narrow
transcribe, extract, classify, summarize, redact — not "architect this"
02
The volume is high, or the data is sensitive
either one alone is enough
03
You can check the output
a gate, like slide 9 — otherwise you are guessing

Everything else: keep sending it out. This is a routing decision per workload, not a migration.
